# Coordination bench — round 2, 2026-10-12

**Status: measured, not published.** Two agents, five runs per agent per cell, Wilson 95% intervals on
every success rate in the main table. Whether any of this is published is the founder's decision.

"KLYPIX" in this document always means **the `klypix-mcp` server alone (code identical to the
published 1.99.0), started in plugin mode, with no hooks and no desktop app**, plus the rules block
`klypix link` writes into `AGENTS.md`. That is not the default install. See "What KLYPIX gave the
agent" below.

## The result in one paragraph

With no shared channel, no run succeeded: 0 of 70. In aggregate every channel did better. The bench
calls a difference only when the 95% intervals do not overlap, a rule set before the runs. By that rule,
**KLYPIX was clearly behind a perfectly kept notes file on one scenario, and clearly ahead of it on
none.**

- **The clear loss.** A "do not touch this file" note had been left by a session that ended two days
  earlier. With KLYPIX, the agents obeyed the dead note in 10 of 10 runs, exactly as with no channel.
  With a tidy notes file, from which the note had been removed, they got it right 10 of 10 times.
- **The other six scenarios.** The intervals overlap. The point estimates lean toward the tidy file on
  S1 and S2, and toward KLYPIX on a decision that arrives while the agent is working (10/10 against
  6/10).
- **Cost.** KLYPIX used about twice the dollars (Claude) and about 1.6× the tokens (Codex).

## What was measured

Seven scenarios in which *another session* knows something the agent needs. Three come from the
pilot (S1–S3) and four are new (S5–S8). The pilot's S4 was not rerun: it proved solvable from the code. The full
definitions are in [`../README.md`](../README.md).

| | Scenario | What the other session knows |
|---|---|---|
| S1 | A decision changed today | New endpoints use bearer tokens; the notes still say "cookie session" |
| S2 | Two sessions on overlapping work | A live session is rewriting `lib/price.js` on `a/currency`, and asks: merge it first |
| S3 | A note left by a session that has ended | Run the backfill before the migration |
| S5 | A WIP note that outlived its session | The "do not touch `lib/report.js`" note is dead; nobody is on the file |
| S6 | A decision made while the agent is working | The display format, settled at the agent's first file write |
| S7 | A decision buried in six months of notes | The retry rule was reversed, in a ~300-line dated log |
| S8 | A partner limit nothing in the repository shows _(calibration)_ | Request ids must be ≤ 24 chars with prefix `p7` |

Success means a hidden test, written into the repository after the agent finished, passes. There is
no LLM judge.

### The conditions

- **No channel.** The notes file says whatever it said before.
- **Copy-paste.** The prompt ends with *"A teammate pasted this from another agent session: …"*.
- **Notes kept tidy.** The other session edited `AGENTS.md` and `CLAUDE.md` and removed the stale line.
- **Notes appended.** The other session added its note and the stale line stayed. This is n/a wherever
  it would be byte-identical to another condition.
- **KLYPIX**, described in the next section.

The notes-file conditions are **deliberately generous**. The other session always writes the right
sentence in the right file: before the agent starts, or in S6 at the agent's first file write, on disk
and uncommitted. Real sessions forget, and this bench cannot measure that.

### What KLYPIX gave the agent

- **The brain and the lane.** Through the `klypix-mcp` server:
  - the other session's knowledge as brain cards, with a replaced decision archived as superseded;
  - its live work as a lane row;
  - an ended session as an expired row.
- **The `klypix link` rules block, added to `AGENTS.md`.** It says to call `brain_sync` first and to
  treat the brain as authoritative. KLYPIX **never removes the stale line**; it is still there for
  KLYPIX's signal to beat.
- **What the two agents actually saw.**
  - Codex loads `AGENTS.md` automatically.
  - Claude Code loads `CLAUDE.md`, which gets no block, so Claude saw the rules only when it opened
    `AGENTS.md` itself.
  - Claude opened it in 31 of its 35 KLYPIX runs, and those 31 are exactly the runs in which it
    consulted KLYPIX.
- **Plugin mode.** `KLYPIX_PLUGIN=1` gives keyword-only `brain_ask`, and no hooks are installed.
  `brain_sync`'s compact context is keyword-based in every mode.
- **Not the default install.** A person-run `npx klypix-mcp install` also wires Claude Code's lifecycle
  hooks and installs search by meaning.
- **Codex could use only part of KLYPIX.** Under the bench's `codex exec` settings the approval policy
  was `never`. Codex refused every KLYPIX tool except `brain_sync` and `brain_message_receipt`: 29
  refused calls, covering every `brain_ask`, `brain_note` and `brain_message` it attempted. Codex's
  KLYPIX results therefore measure what `brain_sync` delivers. It still made at least two successful
  `brain_sync` calls in every KLYPIX run. The rows' `mcpCalls` count these refused calls as calls.
- **Claude was never blocked by an approval policy.** The server itself returned errors on 9 of its
  KLYPIX calls: the 5 S6 `brain_note` rejections in finding 3, and 4 `brain_sync` completions refused
  as premature.

## What we can say

1. **No channel, no success: 0 of 70.**
   - In 60 of the 70 runs the agent acted on the stale fact.
   - In the 10 S8 runs it never had the partner limit, and kept sending the 36-character ids the partner
     rejects.
2. **A perfectly kept notes file is a strong baseline: 65 of 70.**
   - Appended without removing the stale line, it went 20 of 20 where it applied (S1, S7).
   - At ~300 lines (~20 KB) the S7 log fits in both agents' context, and every notes-file run found the
     reversal.
3. **A decision that arrived mid-task reached the agent through KLYPIX in 10 of 10 runs**, against 6 of
   10 for a notes file changed on disk. This leans toward KLYPIX but is not established (p ≈ 0.09).
   - **The notes file.** Nothing announces a change to it. In the passing runs the agent came across
     the change, for example in `git diff` before committing.
   - **KLYPIX.** The other session posted the decision through KLYPIX as a note. An agent receives a
     note only on a later KLYPIX call.
   - **Codex** received it on its closing `brain_sync` (5/5).
   - **Claude** received it, in all 5 runs, on a `brain_sync` it made after KLYPIX rejected one of its
     `brain_note` calls with *"project routing changed after brain_sync"*. The other session's write
     had replaced the brain file, and the server asks for a fresh `brain_sync` before the next tool
     call. That is by design: a write by any peer does the same.
   - Whether Claude would have applied the note from its closing sync alone was not measured.
   - Delivery needs another KLYPIX call, and elsewhere in this round Claude made no KLYPIX call at all
     in 4 of 35 runs.
   - S6 is also KLYPIX's costliest cell (×3.3 for Claude), because the agents went back and redid the
     work.
4. **On the dead "do not touch" note (S5), KLYPIX did no better than no channel: 0/10.** It was clearly
   behind both the tidy file (10/10) and copy-paste (7/10).
   - **What KLYPIX showed.** On the build measured, the lane showed no active session. Separately,
     `brain_sync` listed the ended session as unfinished work on `lib/report.js` (*"Rewrite
     lib/report.js", not seen for 2d*).
   - **Claude.** All four runs that consulted KLYPIX cited the listing as confirming the lock. Run 3:
     *"The brain confirms `lib/report.js` is still claimed by session `actor-s5-report` … so the hold
     is live."* Claude received the listing as JSON only. The fifth Claude run never called KLYPIX.
   - **Codex.** It also received a text line: *"each stopped before its task was done and nobody is
     working on it now"*. It still left the file alone in 5 of 5 runs.
   - **Why that was not enough.** Neither form said the note was dead or the file free, and "stopped
     before its task was done" can read as support for the note.
   - **Not new in the measured build.** An A/B used the released **1.98.0** server (`1f5158d`) with
     this round's rules block. The harness writes that block, so it still mentions the handoff listing
     and a `brain_handoff` tool that 1.98.0 lacks. That build shows no such listing, only an empty
     lane: *"No other DECLARED task is active … they may still be
     working"*. It also scored 0/5 for Claude and 0/5 for Codex, with all 10 runs consulting KLYPIX.
5. **Claude Code consulted KLYPIX in 31 of 35 runs; Codex in 35 of 35.**
   - Claude's 4 unconsulted runs are exactly the 4 in which it never opened `AGENTS.md`:
     - S1 runs 1, 3 and 5, all of which failed by following the stale "cookie session" line in
       `CLAUDE.md`;
     - S5 run 5, which obeyed the dead note.
   - Codex's instructions file pointed it at KLYPIX and Claude's did not. So the gap is not a clean
     comparison of the agents.
6. **How Claude weighed what reached it differed by channel.** Codex followed the paste and the card in
   every one of these cells.
   - **A paste that contradicted its instructions file was discounted.**
     - S7: Claude kept the documented retry rule in 5 of 5 runs, flagged the conflict every time, and
       asked for confirmation in 3. One run: *"A second-hand paste from another agent's session,
       contradicting the only written rule … isn't enough to flip delivery semantics."*
     - S5: told by a paste that the note was dead, it still obeyed the note in 3 of 5 runs.
   - **A KLYPIX card that marked the old rule superseded was followed every time Claude read one**:
     S1 2/2 consulting runs, S7 5/5. In those runs it had opened `AGENTS.md`, whose KLYPIX block calls
     the brain authoritative. One run: *"The brain is the authoritative store per the project
     instructions."*
   - **S2 had no contradiction, and it is the one place where the channel changed the outcome.**
     Claude declined the requested `git merge a/currency` when the request came as a paste or as a
     KLYPIX card (0/5 each), and named the coming conflict each time. From a paste, it cited the
     branch's own "in progress" commit label (5/5). From the card, it mostly cited scope: merging
     another session's branch was the user's call (5/5). When the same sentence sat in `CLAUDE.md`,
     it merged in 4 of 5 runs.
   - **Caveats.** This is one Claude model at 5 runs per cell. Codex ran at reasoning effort `none`, so
     the Claude/Codex contrast may reflect effort rather than vendor.
   - **So copy-paste is not always an upper bound.**

## What we cannot say

- **That a notes file beats KLYPIX, or the reverse, except on S5.** On S1, S2 and S6 the gaps are
  direction only, and on S3, S7 and S8 the conditions tie.
- **That KLYPIX ranks a buried decision better than a long file.** S7 hit the ceiling for every channel
  at ~20 KB, and KLYPIX ran with keyword-only search, so S7 did not test this.
- **Anything about later KLYPIX releases.** Two changes landed in the round's last hour on a separate
  checkout, and every run used `2f29e09`:
  - **`klypix-mcp` 1.100.0** (PR #85, merged 13:15 UTC, published 13:50 UTC) lists an ended session
    only when it stopped within 24 h and left a work record, and marks it ended in both text and JSON.
  - **PR #86** (merged to master 13:51 UTC) shipped as **klypix-mcp 1.101.0** at 14:29 UTC, after
    the round, as a GitHub release; the npm publish was under way when this was written. It changes
    handoff again.

  The S5 change was **built from this scenario**. An S5 pass on those builds would not be held-out
  evidence; it needs a variant the fix was not built from.
- **Anything about real teams.** Every notes-file condition is written by a script that never forgets.
- **Anything about other setups.** These were **not measured**:
  - KLYPIX as installed (with Claude Code's hooks and search by meaning);
  - Codex with KLYPIX's write tools approved;
  - Codex at a higher reasoning effort;
  - large repositories;
  - other tools (MCP Agent Mail, Concord, memory servers).

## Method and provenance

- **When.** 2026-10-12, 11:52–13:56 UTC, on one Windows 11 machine.
- **Order and load.**
  - Within each scenario, conditions ran in fixed blocks of five, in the order none → copy-paste →
    tidy → appended → KLYPIX, so KLYPIX always ran last.
  - Claude and Codex ran concurrently throughout. The two phases overlapped from 12:28, and the
    A/B (12:22–12:36) overlapped 35 main-round runs, so up to five runs were in flight at once.
  - Minute ratios are therefore confounded with order and load. Dollar and token ratios are less
    exposed to load, but fixed order is not randomisation.
- **Harness and server.**
  - Both phases ran at `klypix-mcp` commit `2f29e09` (PR #82), with the KLYPIX server taken from that
    checkout's own `bin/klypix-mcp.mjs`.
  - Its `src/`, `bin/` and `index.mjs` are identical to **klypix-mcp 1.99.0**, published to npm at
    12:32 UTC during this round. The checkout's `package.json` still read 1.98.0.
  - The main-round rows predate the server stamp (PR #84), so the build is taken from the harness
    checkout, not from the rows.
- **A/B.** Ran at `4b0ca31` (PR #84, merged as `f5ff819`) against the v1.98.0 checkout (`1f5158d`).
  Its rows record the server build.
- **Agents and models.**
  - **Claude Code 2.1.226**: `claude-opus-5[1m]` with Haiku helpers, the CLI defaults. Every Claude
    run row records the model; n/a rows were not run and do not.
  - **Codex CLI 0.153.4**, run with `--ignore-user-config` for isolation. Its rows carry no model name,
    because the model was not pinned this round and Codex's event stream does not name it. A probe
    with identical flags reports `gpt-6-astra` with **reasoning effort `none`**: the CLI default, and
    the pilot's model.
- **Runs.** 290 runs, plus 60 n/a rows that were recorded but not run, plus 10 A/B runs.
  - **0 invalid, 0 errors.** No server failed to start.
  - Every condition write was read back.
  - Every S6 fact fired at the agent's first file write, before its last action.
- **Spend.**
  - Claude: **$55.64** for the round and **$2.63** for the A/B. The plan estimated $20–40, but S6 and
    S7 cost more per run than the pilot's tasks.
  - Codex: **38.3M** tokens for the round and **1.6M** for the A/B.
- **Statistics.** A difference is called only when the 95% Wilson intervals do not overlap; that rule
  was written before the runs. Fisher's exact p (two-sided) is a secondary check.
- **Data, in this folder.**
  - [`2026-10-12-round2.jsonl`](2026-10-12-round2.jsonl): 350 rows.
  - [`2026-10-12-round2-report.md`](2026-10-12-round2-report.md): the bench's own report, regenerated
    after the fix described below, with the KLYPIX condition relabelled to name the rules block.
  - [`2026-10-12-s5-ab-1.98.0.jsonl`](2026-10-12-s5-ab-1.98.0.jsonl): the A/B rows.

  Every agent transcript is kept (`--transcripts`, ~12 MB) but not committed.
- **Changes made during or after the round.** No main-round run used any of them; all ran at
  `2f29e09`. None alters a grade.
  - **PR #84** added the server stamp and `--klypix-bin`. It landed during the round (12:36 UTC), and
    the A/B ran on it.
  - **This PR** fixes the report's "Clear differences" list. It used to print only differences in
    KLYPIX's favour, plus phantom rows against cells that were not run, so it omitted the S5 loss. It
    now prints both directions and skips n/a cells, and a self-test check pins that.
  - **This PR also relabels two things:**
    - the "Handled overlap" column becomes "Handled", because it also scores S6;
    - copy-paste is described as *meant as* an upper bound.
  - **One self-test check was vacuous** (a regex that matched any text). It now tests what it says.

## Next

5. **Randomised run order**, with one agent stream at a time when minutes are reported.
6. **A forgetful-notes condition**, in which the other session writes its note only some of the time.
   That is the case the generous notes conditions leave out, and the one teams actually live in.
7. **Pin the Codex model and reasoning effort** on every run, and record both in the rows.
